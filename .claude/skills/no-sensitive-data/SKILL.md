# Никаких чувствительных данных в репозитории

Репозиторий публикуется на GitHub. Всё, что попало в коммит, считается опубликованным навсегда (история, форки, кэши).

## Что запрещено коммитить

- Реальные выписки и выгрузки банков (PDF, XLSX, CSV, 1С txt) и любые фрагменты из них: назначения платежей, ФИО, названия контрагентов, номера документов.
- Реальные идентификаторы: ИНН/КПП/ОГРН людей и компаний из выписок владельца, номера счетов (20 цифр), номера и токены карт, телефоны, e-mail, адреса, остатки и обороты по реальным счетам.
- Секреты: пароли, `ENCRYPTION_MASTER_KEY`, токены API банков, client_secret, сертификаты `.pfx`, `server.json`, `.env`, cookie/bearer-токены, дампы БД.
- Скриншоты приложения с реальными данными (снимки для проверки хранить только в scratchpad).

Публичная справочная информация допустима: ИНН и БИК банков (ПАО Сбербанк 7707083893, БИК 044525225), названия банков и брендов магазинов, MCC.

## Как делать примеры и тесты

- Реквизиты только синтетические: счета вида `40702810100000000123` (нули в середине), ИНН `77000000xx` / `7700000000xx` или `123456789012`, телефон `+7 900 123-45-67`, e-mail `*@example.com`, имена «Иванов Иван Иванович», «ООО "Ромашка"», отделение «№0001».
- Структура файла копируется с реального (колонки, заголовки, форматы дат и сумм), содержимое — вымышленное. В комментарии к тесту пишите «все реквизиты вымышленные».
- Суммы и остатки не должны совпадать с реальными.
- Для проверки парсеров на настоящих файлах используйте `docs/vendor/` (в `.gitignore`) и `tools/StatementProbe`; результаты в чат и в файлы репозитория не выносить.
- Демо-данные в БД — только на локальной машине; демо-пользователь задаётся через `.env`, не в коде.

## Перед коммитом

1. `python tools/secret-scan.py --staged` (или `git config core.hooksPath .githooks` один раз, дальше проверка идёт сама). На GitHub тот же скрипт запускается в Actions.
2. Просмотреть diff глазами: имена, ИНН, счета, телефоны, ключи, base64-строки, скриншоты.
3. Если что-то реальное уже попало в историю — не «затирать» следующим коммитом, а переписать историю до пуша (`git filter-repo --replace-text`) и сообщить владельцу; если уже запушено — ротация секретов и force-push с его согласия.

## Где живут секреты

`.env`, `secrets/`, `docs/vendor/`, `server.json` в папке данных приложения — всё в `.gitignore`. Новые файлы с секретами добавляйте туда же, а в `.env.example` — только пустые значения и комментарии.
