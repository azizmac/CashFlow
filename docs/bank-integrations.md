# CashFlow AI — источники данных российских банков (API / MCP)

Дата исследования: 2026-09-03. Дополнение 2026-09-04: практические карточки по каждому банку/брокеру и MCP-интеграция — в каталоге **[banks/](banks/README.md)**.

## 1. Главный вывод

Официального API для **физлиц** у Сбера и Т-Банка (счета/карты/кредиты/вклады) на сегодня **нет**. Официальные API — только для бизнеса (ИП/ЮЛ) и для инвестиций (Т-Инвестиции). Единый стандарт Открытых API ЦБ РФ для физлиц принят (введение с 01.10.2026), но реальный обмен данными ожидается не раньше 2027 г. после принятия федерального закона.

Значит, архитектура приложения должна быть **многоканальной**: официальные API там, где они есть, плюс импорт выписок и парсинг уведомлений как основной канал для физлиц, с готовностью подключить Open API ЦБ, когда он заработает.

## 3. Как закрыть каждую потребность CashFlow AI

| Потребность | Сейчас | После запуска Open API ЦБ |
|---|---|---|
| Баланс карт/счетов физлица | push-парсинг (Android), импорт выписки, ручной ввод | `GET /balances`, `/payment-card-balances` |
| История транзакций | импорт выписок + push | `GET /transactions` с фильтром по датам |
| Инвестиции | T-Invest API/MCP, Finam, ALOR, БКС | те же брокерские API (Open API покрывает брокеров с 2026–27) |
| Кредиты, вклады | импорт выписки/скриншота, ручной ввод | `GET /products` (productType) |
| Расчётный счёт ИП | T-API, Sber API, Alfa API | то же |
| Курсы валют/ставки | API ЦБ РФ (`cbr.ru/scripts/XML_daily.asp`), MOEX ISS | — |

## 4. Рекомендуемая архитектура коннекторов

1. **Ядро** — единая модель `Account / Transaction / Position / Product`, к которой приводятся все источники (нормализация знаков, валют, дедупликация по хэшу операции, распознавание переводов между своими счетами).
2. **Коннекторы** как плагины с одинаковым интерфейсом `fetchAccounts / fetchTransactions / fetchPositions`:
   - `tinvest` — gRPC (официальный SDK есть для .NET, Python, Java, Go) — **первый к реализации**.
   - `tbusiness`, `sberbusiness`, `alfabusiness` — REST, для ИП/ЮЛ.
   - `statement-import` — парсеры файлов (PyMuPDF/pandas или .NET аналоги), поддержка Сбер/Т-Банк/ВТБ/Альфа/Совкомбанк.
   - `push-listener` — только Android, регэкспы по шаблонам уведомлений банков.
   - `openapi-cbr` — заготовка под стандарт СТО БР (FAPI/OIDC, согласия) — активировать в 2027.
3. **MCP-слой**: AI-агент приложения подключает официальный T-Invest MCP напрямую; для остального — свой внутренний MCP-сервер над нормализованной БД (не над банками).
4. **Безопасность**: токены только на устройстве или в зашифрованном хранилище; никакого хранения логина/пароля от интернет-банка (это ещё и нарушение договора с банком).

## 5. Ограничения и риски

- Open API ЦБ: сроки перенесены в 10.2025, законопроект не принят, тарифы за данные разрешены — планировать как «2027+».
- Неофициальные MCP/скрейперы — источник для MVP-экспериментов, не для продакшена.
- iOS: нет доступа к SMS/push → только импорт файлов и официальные API.
- T-Invest API отмечается как нестабильный по соединению → нужны ретраи и кэш.

## 6. Подключение «через авторизацию» — что выяснилось 2026-09-03

**Как устроен мультибанк Т-Банка.** Счета Сбера, ВТБ и Альфы в приложении Т-Банка работают по Открытым API Банка России: на «Финополисе-2025» банки подписали соглашения (Т-Банк ⟷ Сбер, Т-Банк → ВТБ/Альфа, Альфа ⟷ ВТБ), обмен идёт на платформе Ассоциации ФинТех, согласие клиент даёт, войдя в другой банк из приложения Т-Банка. Участники — только банки пилота; доступа для сторонних сервисов нет и не будет до принятия закона об Открытых API (ориентир — 2027 г.). Для CashFlow это означает: «как у Т-Банка» для физлиц сделать нельзя, единственный канал для физлица — файлы выписок.

**Что реально доступно ИП/ЮЛ (и реализовано в приложении).**

| Банк | Способ | Что нужно от пользователя | Статус в CashFlow |
|---|---|---|---|
| Сбер (Sber API, прямая интеграция) | OAuth 2.0 Authorization Code + PKCE через СберБизнес ID, mTLS-сертификат, refresh_token одноразовый | зарегистрировать приложение в СберБизнесе, вписать client_id/secret/сертификат в конфиг сервера, один раз войти в банке | ✅ `/oauth/sberbusiness/start` + коннектор `SberBusinessConnector` (IOAuthConnector) |
| Альфа-Банк (Alfa API / Alfa ID) | OAuth 2.0 Authorization Code, без mTLS | зарегистрировать приложение на developers.alfabank.ru, вписать client_id/secret | ✅ `/oauth/alfabusiness/start` + `AlfaBusinessConnector`; URL методов в конфиге, требуют сверки с инструкцией банка (скачанный PDF v27 оказался повреждён) |
| Т-Банк (T-API, Т-Бизнес) | самостоятельный токен из ЛК (90 дней с последнего использования, привязка к IP) | выпустить токен с правом «Счета и выписки» | ✅ `TBankBusinessConnector` по токену; партнёрский OAuth T-Business ID (`/oauth/tbankbusiness/*`, эндпоинты id.tbank.ru/auth/authorize|token|introspect, scope accounts/balance/statements) реализован, но доступ дают только партнёрам от 30 тыс. авторизаций/мес |
| ВТБ, Точка, другие | API для клиентов нет / только партнёрский | экспорт в 1С из интернет-банка | ✅ `ClientBankExchangeParser` определяет банк по содержимому |

**Форматы выписок СберБизнеса** (проверено на реальных файлах ИП и ООО):

| Формат | Что внутри | Парсер |
|---|---|---|
| «Экспорт в 1С» `kl_to_1c.txt` (cp1251) | контрагент, ИНН/КПП, счета, БИК, назначение; для бизнес-карты — магазин в назначении («Покупка PURCHASE_CB в ТУ Сбербанка SUPERMARKET …») | `ClientBankExchangeParser` — рекомендуемый |
| «Выписка операций по лицевому счёту» XLSX/PDF | дата, ВО, № документа, БИК, корр. счёт, дебет/кредит — без названий | `SberBusinessStatementParser` (краткий режим, описание по коду ВО и балансовому счёту) |
| Расширенная выписка XLSX (СберКазначейство) | то же + счёт/ИНН/название обеих сторон, банк, назначение; в ячейках по три строки | `SberBusinessStatementParser` (расширенный режим) |
| DOCX | дубликат PDF | не читается, не нужен |

**Сбер физлицо**: PDF «Выписка по счёту дебетовой карты» — две строки на операцию (дата-время-категория-сумма-остаток; дата-код авторизации-описание). Код авторизации стабилен → используется как внешний ID. `SberPdfStatementParser`.

**Не удалось получить**: developer.sberbank.ru отдаёт ERR_CONNECTION_RESET даже из РФ (2026-09-04), openbankingrussia.ru не отвечает; PDF-инструкция Альфы (`docs/vendor/alfa-api-manual.pdf`) дважды скачана через текстовый декодер — байты ≥0x80 заменены на U+FFFD, потоки не восстанавливаются, нужна бинарная загрузка (Ctrl+S в браузере или `curl -o`). Значения URL для Сбера взяты из ранее используемого коннектора (fintech.sberbank.ru:9443) и стандартной схемы СберБизнес ID (`/ic/sso/api/v2/oauth/authorize|token`); для Альфы — из публичных примеров и вынесены в конфигурацию.
