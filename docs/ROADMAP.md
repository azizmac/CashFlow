# CashFlow AI — дорожная карта

Файл для людей и для любых ИИ-агентов, которые будут работать с проектом. Перед задачей прочитайте `CLAUDE.md` в корне (стек, архитектурные правила, конвенции) и этот файл (что сделано, что дальше, как проверять). Пункты пронумерованы, чтобы на них можно было ссылаться: «сделай R-07».

## Как пользоваться

- Берите задачу из раздела «Очередь», переносите её в «В работе» с датой, по завершении — в «Сделано» с коротким итогом и способом проверки.
- Каждая задача самодостаточна: контекст, файлы, критерии приёмки, как проверить. Если чего-то не хватает — сначала дополните описание, потом кодите.
- UI-задачи выполняются по дизайн-системе `docs/design/cashflow-ai-ui-mockups/project/CashFlow AI.dc.html` и скиллам в `.claude/skills` (apple-design, emil-design-eng, animate, review-animations). Серверные — через `CashFlow.Server`, наружу только DTO.
- Отчёт о выполнении и коммиты — на русском. Коммитить только по просьбе владельца.

## Очередь (по приоритету)

### P1 — довести текущую сборку

- **R-03. Тесты Application и API.** Интеграционные тесты на `LedgerQueries`, `ImportService`, `ConnectionsService` (Testcontainers PostgreSQL или временная база) и на `MapCashFlowApi` (WebApplicationFactory): изоляция пользователей (403/404), импорт multipart, маскирование в DTO. Критерий: `dotnet test` покрывает границу DTO; ни один тест не отдаёт сущности домена наружу.
- **R-04. Экран «Подключения» во встроенном сервере.** `BankOAuthEndpoints` живут в `CashFlow.Web` и требуют cookie-сессию; в настольной сборке OAuth не работает. Перенести старт/колбэк OAuth в `CashFlow.Server` с bearer-авторизацией и системным браузером (loopback redirect `http://127.0.0.1:{port}/oauth/.../callback`). Критерий: из MAUI на Windows подключение Сбера открывает браузер и возвращается в приложение.
- **R-05. Установщик настольной сборки.** MSIX или Inno Setup для Windows, `.pkg` для macOS; опция «поднять PostgreSQL в Docker» или подсказка с командой. Критерий: чистая машина, установка, первый запуск → экран входа без правки файлов.
- **R-06. Мобильные цели.** `dotnet workload install maui`, сборка Android (APK) и iOS с `-p:MobileTargets=true`, проверить safe-area, таббар, `InputFile` на телефоне, «Поделиться»/экспорт файла. Критерий: APK ставится и входит на удалённый сервер.

### P2 — экраны макета, для которых нужен новый функционал

- **R-07. Прогноз (артборд 2b).** Детектор регулярных потоков (зарплата, аренда, подписки, налоги) по истории операций → сущность `RecurringFlow`, DTO `ForecastDto` (баланс через 1/3/6 месяцев, график, список потоков, «month ahead»). Экран `/forecast` по макету + пункт в навигации. Критерий: на реальных выписках владельца находятся минимум аренда и налоги ИП; прогноз пересчитывается при импорте.
- **R-08. ИИ-чат / командная строка ⌘K (артборд 1f).** Серверный эндпоинт `/api/assistant` поверх Claude API (модель по умолчанию `claude-sonnet-5`, ключ в конфигурации сервера, наружу не отдаётся), инструменты — только чтение через `ILedgerQueries`; ответы с ссылками на операции. Экран: нижняя строка «Спросить о тратах…» на телефоне, палитра ⌘K на десктопе, кнопка ✦ в таббаре переключается с импорта на чат. Критерий: вопрос «сколько я потратил на еду в августе» даёт сумму и список; ключ не утекает в клиент.
- **R-09. Категоризация ИИ.** Тот же ключ: предложения категорий для «Без категории» (сейчас только правила/MCC/контрагент), пакетно и с уверенностью; тумблер «Privacy & AI» в настройках (локально/облако/выкл). Критерий: предложения появляются с чипом ✦ и принимаются одной кнопкой.
- **R-10. Объединение контрагентов (артборд 1c «merge suggested»).** Поиск дублей по ИНН/нормализованному имени/счёту, DTO `MergeSuggestionDto`, команда `MergeCounterpartiesAsync`, карточка-предложение в списке. Критерий: «ООО Ромашка» и «РОМАШКА ООО» с одним ИНН сливаются, операции переносятся.
- **R-11. Биометрия и блокировка приложения (артборд 2a «Войти по Face ID»).** MAUI: `Plugin.Maui.Biometric` или платформенные API; PIN как запасной вариант; блокировка при сворачивании. Критерий: повторный вход без пароля на телефоне и Windows Hello.
- **R-12. Код восстановления (артборд 2a, шаг 3).** 24 слова BIP-39 для восстановления доступа к шифрованным полям и аккаунту; хранить только хэш. Требует проработки безопасности — начать с ADR (`engineering:architecture`).

### P3 — качество и полировка

- **R-18. Перекатегоризация существующих операций.** Команда «пересчитать категории» (кнопка в Категориях и вызов после изменения правил): прогнать `RuleCategorizer` по операциям без ручной категории, чтобы исправления правил (например, запрет доходной категории для расхода) применялись к уже загруженным данным. Критерий: после нажатия в обзоре демо-данных «Доход ИП» исчезает из расходов.

- **R-13. Анимации по скиллам.** Прогнать `review-animations` и `find-animation-opportunities` по `app.css` и страницам: переходы карточки операции (шторка снизу на телефоне, `--ease-drawer`), стаггер списка по дням ≤ 50 мс, скелетоны загрузки вместо «Загрузка…», без анимаций на клавиатурных действиях. Критерий: таблица Before/After в отчёте, все переходы < 300 мс.
- **R-14. Дизайн-спецификации экранов.** Для каждого экрана сгенерировать handoff-спеку (`design:design-handoff`) в `docs/design/specs/`: токены, состояния, пустые/ошибочные/загрузочные состояния, брейкпоинты. Критерий: новый агент может сверстать экран без открытия `.dc.html`.
- **R-15. Доступность.** Фокус-кольца на стеклянных поверхностях, ARIA у чипов и сегментов, порядок фокуса в таббаре, контраст `--muted` в светлой теме ≥ 4.5:1. Проверить `design:accessibility-review`.
- **R-16. Наблюдаемость сервера.** Структурированные логи, `/healthz`, счётчики импорта; в настольной сборке — кнопка «Открыть server.log» в настройках.
- **R-17. Альфа-Банк.** Вернуться к `AlfaBusinessConnector`, когда появится рабочая документация (PDF в `docs/vendor` повреждён).

## Правила приёмки для любой задачи

1. Сборка: `dotnet build src/CashFlow.Web` и `dotnet build src/CashFlow.Maui -f net9.0-windows10.0.19041.0` (если менялся UI/клиент).
2. Тесты: `dotnet test tests/CashFlow.Domain.Tests` зелёные; новые парсеры — с реальными файлами через `tools/StatementProbe`.
3. Сервер: `docker compose up -d --build web`, `curl http://localhost:8080/Account/Login` → 200; встроенный сервер приложения: `curl http://127.0.0.1:47831/api/profiles` → 401 без токена.
4. Граница безопасности: наружу не ушли сущности домена, полные номера счетов, телефоны, `CredentialRef`, ключи API.
5. Тексты для пользователя — на русском; документация обновлена (`README.md`, при смене стека — `CLAUDE.md`, здесь — статус задачи).
