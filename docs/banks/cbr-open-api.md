# Открытые API ЦБ РФ (для физлиц) — стандарт будущего канала

## Суть

Единый стандарт обмена данными между банками и «третьими сторонами» (финансовыми агрегаторами) — аналог PSD2/Open Banking. Регулятор — ЦБ РФ, разработка стандартов — Ассоциация ФинТех (СТО БР ИББС). Это **закроет нашу главную дыру**: данные карт/счетов/вкладов/кредитов физлиц без файлов и серых каналов.

- Витрина ЦБ: <https://www.cbr.ru/fintech/api/>
- Стандарт получения информации о счетах: ОД-2890 от 19.12.2025 — <https://cbr.ru/Content/Document/File/185563/20251219_od_2890.pdf>
- Спецификации (сообщество): <https://wiki.opendatarussia.ru/specifications/accounts/v20/account-info-openapi-pe>
- Итоги/сроки: <https://rtln.ru/blog/otkrytye-api-banka-rossii-itogi-2025-goda-novye-sroki-obnovlenie-standartov/>

## Статус и сроки (на 2026-09)

- Стандарт v2.0 **введён с 01.10.2026**, но обязательные сроки подключения банков перенесены (решение ЦБ 10.2025); реальный обмен — **ожидается с 2027**, после принятия ФЗ о открытых API (законопроект не принят; банкам разрешат брать плату за передачу данных).
- Планируем как «2027+», не блокируем MVP: каналы «выписка + API бизнеса» работают уже сейчас.

## Протокол

- FAPI (FA). OpenID Connect: клиент (мы) регистрируется у банка/в реестре, пользователь даёт **consent** (согласие) через авторизацию банка.
- OAuth2 Authorization Code + PKCE → access/refresh-токены scoped на consenting пользователя.
- Scope для физлиц: `obru_accounts_pe` (и родственные по разделам стандарта).

## Эндпоинты стандарта (разделы Accounts/Products)

| Эндпоинт | Данные |
|---|---|
| `GET /accounts` | счета физлица (номера скрыты частично, тип, валюта, статус) |
| `GET /balances`, `GET /payment-card-balances` | остатки по счетам/картам |
| `GET /transactions?from&to&account-id` | история операций → `ExternalTransaction` |
| `GET /payment-products`, `GET /payment-cards` | карты и привязки |
| `GET /products?productType=…` | вклады/кредиты (ставка, срок, остаток долга) → `ExternalProduct` |

## Как подготовиться в CashFlow

1. `ConnectorType.CbrOpenApi` — заготовка уже есть.
2. Коннектор `CbrOpenApiConnector : ReadOnlyConnectorBase` с секретами `client_id`, `client_secret`, `refresh_token`; `RequiredSecrets` = они же; `OnSecretsRotated` — как в Sber-коннекторе.
3. UI «Подключения»: кнопка «Согласиться с банком» → redirect на авторизацию банка → callback с code → обмен на токены (нужен публичный HTTPS-callback в `CashFlow.Web`).
4. Маппинг: один коннектор покрывает все банки-участники → поле `Institution` берём из ответа (bank id в стандарте — BIC/участник своп-реестра).
5. Тесты на песочнице АФТ, когда она откроется для третьих сторон (⚠️ доступ к песочнице — отдельная заявка, условия уточнить).

## Риски

- Сдвиг сроков (уже сдвигались дважды) — не завязывать roadmap фич физлиц на него.
- Тарификация данных банками — заложить в экономику: для self-hosted всё равно платит сам пользователь за своё согласие.
- MVP-агрегаторам без лицензии/регистрации доступ могут не дать — следить за 151-ФЗ/НПА ЦБ в момент запуска.
